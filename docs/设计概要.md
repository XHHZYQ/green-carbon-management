## 1 引言

### 1.1 编写目的

本文档依据《绿色低碳智慧管控系统 软件需求规格说明书 V1.2》，给出系统的总体设计、技术选型、项目结构、数据库设计、接口设计、模块设计与开发计划，作为后续编码、测试与软著材料的依据。

### 1.2 项目背景

园区、企业办公楼等场所内存在大量智能化电气设备与办公设备，普遍存在"家底不清、能耗不明、管控不力、碳排不算"的问题。本系统面向上述场景，提供设备接入、设备台账、远程控制、能耗监测、碳排放核算、告警运维与数据可视化能力，实现"省能、省钱、合规、安全"。

### 1.3 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| 驾驶舱 | 系统首页的数据大屏，集中展示关键指标与图表，只读总览 |
| 台账 | 设备的档案清单 |
| 设备接入 | 登记设备、配置通信连接参数并使其上线的过程 |
| 测点 | 设备上可被采集的数据点，如电压、电流、温度、累计电量 |
| 控制点 | 设备上可被下发指令的操作项，如电源开关、温度设定、运行模式 |
| 碳因子 | 单位能耗对应的二氧化碳排放量系数 |
| 范围一/二/三 | 温室气体核算分类：直接排放 / 外购能源间接排放 / 其他间接排放 |
| 组态图 | 以图形元件可视化展示设备与测点实时状态的画面 |

### 1.4 设计目标与原则

1. **简洁优先**：在覆盖完整需求的前提下，架构、数据库与项目结构尽量简洁，便于快速形成软著材料。
2. **数据模拟**：V1.0 全部设备数据、能耗数据、控制下发、告警与通知均由系统内置模拟生成，不接入真实硬件。
3. **接口预留**：设备接入与设备控制按真实系统的形态设计（协议、连接参数、指令模型），保证后续可平滑对接真实设备。
4. **可视化优先**：驾驶舱与图表为重点，界面清晰美观，适配大屏展示。
5. **统一规范**：全局布局、样式、主题统一，主题色为显眼的科技蓝。

## 2 总体设计

### 2.1 技术选型

前后端分离，前后端代码置于同一 Monorepo 仓库。

**后端**

| 项 | 选型 |
| --- | --- |
| 语言/运行时 | Python 3.12，依赖用 `uv` 管理 |
| Web 框架 | FastAPI ≥0.115 + uvicorn[standard] |
| ORM/模型 | SQLModel ≥0.0.22 + SQLAlchemy[asyncio] ≥2.0，**异步 Session** |
| 数据库 | PostgreSQL，驱动 **asyncpg ≥0.30** |
| 校验/配置 | Pydantic ≥2.9 + pydantic-settings |
| 鉴权 | PyJWT + bcrypt（密码哈希） |
| 定时/模拟 | APScheduler ≥3.10（模拟采集、定时控制、定时报表） |
| 导出 | openpyxl（Excel）、reportlab（PDF） |
| 验证码 | Pillow |

**前端**

| 项 | 选型 |
| --- | --- |
| 框架 | Vue 3.5 + TypeScript 5.x |
| 构建 | Vite 6 + pnpm（Node.js > 22） |
| UI 组件 | Element Plus 2.9 |
| 图表 | ECharts 5.5 + vue-echarts |
| 状态管理 | Pinia 2.x |
| 路由 | Vue Router 4.x |
| 请求 | Axios 1.x |
| 样式 | **SCSS**（sass） |
| 提效 | unplugin-auto-import、unplugin-vue-components、@element-plus/icons-vue |

**关键决策**

| 项 | 决策 |
| --- | --- |
| 数据库访问 | 异步 `create_async_engine` + `AsyncSession`（`postgresql+asyncpg://`） |
| 建表方式 | `SQLModel.metadata.create_all` + 独立 seed 脚本，不引入 Alembic |
| 数据库 | 库名 `green_carbon`，端口 `5433`，用户 `green_carbon`（本地 WSL Docker 实际映射端口） |
| 主题 | 科技蓝主色 `#1E6FFF`，SCSS 变量 + Element Plus 变量覆盖；驾驶舱/大屏深色变体 |
| 时间格式 | 全表 `timestamp`，填充与展示统一 `YYYY-MM-dd hh:mm:ss` |

### 2.2 系统总体架构

系统采用分层架构：前端表现层通过 HTTP/JSON 调用后端接口层，后端经业务层访问数据库层。

```
┌──────────────────────────────────────────────────────────────────┐
│                        表现层（浏览器）                            │
│   Vue 3 + TS + Vite + Element Plus + ECharts                       │
│   登录页 / 统一 Layout / 驾驶舱大屏 / 17 模块业务页面               │
│   Pinia 状态 · Vue Router 动态路由 · Axios 请求封装                │
└───────────────────────────────┬──────────────────────────────────┘
                                │ HTTP / JSON（REST，JWT 鉴权）
┌───────────────────────────────▼──────────────────────────────────┐
│                      接口层（FastAPI · api/v1）                     │
│   路由分组：auth / dashboard / monitor / devices / points / data   │
│   control / scenes / link-rules / energy / price / fee / carbon    │
│   quotas / alarms / work-orders / notify / reports / config / system│
│   中间件：CORS · 统一响应 · 全局异常 · 鉴权依赖                     │
└───────────────────────────────┬──────────────────────────────────┘
                                │ 调用
┌───────────────────────────────▼──────────────────────────────────┐
│                     业务层（services）                              │
│   登录鉴权 · 设备接入 · 测点采集 · 设备控制 · 场景联动 · 能耗统计    │
│   电价计费 · 碳排核算 · 定额考核 · 告警工单 · 消息通知 · 报表导出     │
│   调度器（APScheduler）：模拟采集 / 定时控制 / 定时报表 / 告警判定    │
└───────────────────────────────┬──────────────────────────────────┘
                                │ SQLModel（异步）
┌───────────────────────────────▼──────────────────────────────────┐
│                   数据层（PostgreSQL · asyncpg）                    │
│   系统权限 / 基础配置 / 设备测点 / 控制场景 / 能耗费用碳排 /         │
```

### 2.3 系统运行架构

- 部署形态：内网部署，前端静态资源由 Nginx（或 Vite 开发服务器）托管，后端由 uvicorn 提供 API 服务，数据库为 PostgreSQL（本地 WSL Docker）。
- 访问链路：浏览器 → 前端静态资源 → `/api/v1/*` 反向代理 → FastAPI → PostgreSQL。
- 客户端要求：主流浏览器（Chrome/Edge），分辨率 ≥ 1366×768，驾驶舱建议大屏。

### 2.4 前后端交互与鉴权

1. 登录：前端提交用户名、密码、验证码，后端校验通过后签发 JWT。
2. 鉴权：后续请求在请求头携带 `Authorization: Bearer <JWT>`；后端解析并校验有效期与用户身份。
3. 统一响应体：`{ "code": 0, "message": "ok", "data": ... }`，成功 `code=0`，失败返回业务错误码与提示。
4. 全局异常：业务异常、参数校验异常、未认证异常、未授权异常由统一异常处理器转换为标准响应。
5. 权限：基于角色的访问控制（RBAC），前端按菜单权限渲染、后端接口再次校验，前后端双重控制。

## 4 数据库设计

### 4.1 设计约定

- 命名：表名与字段名用下划线小写；表前缀按域区分（sys/cfg/dev/mon/ctrl/scene/energy/carbon/quota/alarm/wo/notify/report）。
- 主键：所有表统一 `id`（int，自增）。外键统一命名 `xxx_id`，指向对应表的主键。
- 通用字段：所有表含 `id`、`created_at`、`updated_at`（timestamp）；业务表视需要含 `remark`、`status`。
- 数据类型：`int / varchar / numeric / boolean / timestamp / date / text / jsonb`。
- 时间：统一 `timestamp`，填充与展示格式 `YYYY-MM-dd hh:mm:ss`。
- 枚举：以 `varchar` 存编码，含义由 `cfg_dict_item` 维护。

> 下表每张表列出：字段名 类型（**PK**=主键，**FK→表**=外键）。未标注类型的字段均为 `varchar`。

- 用户与权限：`sys_user` —(sys_user_role)— `sys_role` —(sys_role_menu)— `sys_menu`。
- 设备主线：`cfg_device_type` / `cfg_protocol` → `dev_device` →（`dev_device_conn` 连接参数 / `dev_point` 测点 / `dev_control_point` 控制点 / `dev_collect_task` 采集任务）；`dev_point` → `dev_data` 采集数据。
- 设备归属：`dev_area` 区域树 ↔ `dev_device`。
- 控制链路：`dev_device` + `dev_control_point` → `ctrl_command`（控制记录）；`scene_info` → `scene_action` → `dev_device`。
- 能耗主线：`dev_data` → `energy_stat`（能耗统计）→ `energy_fee_stat`（按 `energy_price_plan` 计费）；`energy_stat` × `cfg_carbon_factor` → `carbon_emission`（碳排）。
- 定额主线：`energy_quota` → `quota_monitor` → `quota_assess`。
- 告警闭环：`dev_data` 命中 `alarm_rule` → `alarm_info` →（转）`wo_work_order`，并经 `notify_rule` → `notify_message` / `notify_send_log` 通知。
- 报表：`report_template` → `report_record` / `report_subscribe`。

> 合计 **57 张表**：sys 7、cfg 9、dev 11、mon 2、ctrl 2、scene 5、energy 5、carbon 2、quota 3、alarm/wo 3、notify 5、report 3。

## 6 模块设计

> 每个模块给出：功能点（对应需求 FR 编号）→ 页面 → 主要接口 → 主要数据表 → 设计要点。页面与路由对照见第 11 章附录。

### 6.1 登录与权限（FR-1）

- 功能点：FR-1-01 登录、FR-1-02 图形验证码、FR-1-03 退出登录、FR-1-04 修改密码、FR-1-05 菜单与权限控制、FR-1-06 登录日志
- 页面：登录页
- 接口：/auth/captcha、/auth/login、/auth/logout、/auth/me、/auth/password、/menus/routes
- 数据表：sys_user、sys_role、sys_user_role、sys_menu、sys_role_menu、sys_login_log、sys_oper_log
- 要点：JWT 鉴权（Bearer）；图形验证码内存态存储；连续失败 5 次锁定 10 分钟；菜单/权限由角色驱动，前端按菜单树动态生成路由、后端接口二次校验。

### 6.2 数据驾驶舱（FR-2）

- 功能点：FR-2-01 关键指标卡、FR-2-02 能耗趋势、FR-2-03 分项能耗占比、FR-2-04 区域能耗排名、FR-2-05 碳排放概览、FR-2-06 设备状态分布、FR-2-07 实时告警滚动、FR-2-08 大屏模式、FR-2-09 费用与定额概览
- 页面：首页数据大屏
- 接口：/dashboard/overview、/energy-trend、/energy-item-ratio、/area-rank、/carbon-overview、/device-status、/latest-alarms、/fee-quota
- 数据表：无独立表，聚合 dev_device、dev_data/energy_stat、carbon_emission、alarm_info、energy_fee_stat、quota_monitor
- 要点：只读总览页；默认 30 秒自动刷新；支持全屏大屏（scale 等比缩放 1920×1080）。

### 6.3 实时监控（FR-3）

- 功能点：FR-3-01 实时数据卡片、FR-3-02 设备组态图、FR-3-03 区域平面图、FR-3-04 实时曲线、FR-3-05 秒级自动刷新、FR-3-06 组态编辑、FR-3-07 快照导出、FR-3-08 设备定位联动

## 7 前端设计

### 7.1 布局与主题

- 登录页：独立全屏布局，科技蓝渐变背景，含验证码。
- 业务页：统一 Layout = 顶栏（折叠按钮 + 面包屑 + 用户下拉）+ 侧边栏（多级菜单，支持折叠）+ 内容区。
- 驾驶舱/大屏：全屏深色布局，`scale` 等比缩放适配 1920×1080，支持全屏。
- 主题：SCSS 变量集中定义科技蓝主色 `#1E6FFF` 及辅助色/中性色，并通过 Element Plus 的 SCSS 变量覆盖实现全局统一。

### 7.2 路由与权限

- 路由 = 静态路由（登录页、Layout、404）+ 后端菜单生成的动态路由。
- 登录成功后调用 `/menus/routes` 获取菜单树，前端将其转换为路由记录并 `addRoute` 到 Layout 下。
- 组件映射：以 `import.meta.glob('../views/**/*.vue')` 建立"菜单 component 路径 → 组件"映射。
- 路由守卫：无 Token 跳登录页；有 Token 时首次进入加载用户信息与菜单并注册动态路由；401 自动清理登录态并跳登录。
- 菜单可见性由后端 `visible` 字段控制，无权限页面不出现在菜单、直接访问亦不可达。

### 7.3 公共组件

| 组件 | 说明 |
| --- | --- |
| ChartBox | ECharts 封装：自适应尺寸、30 秒轮询、加载态与空态 |
| QueryBar | 查询条件栏（关键字/下拉/日期范围 + 查询/重置） |
| DataTable | 表格封装：分页、加载态、操作列、空态 |

- ECharts 按需引入，统一配色与字号；驾驶舱/能耗/碳排/费用图表风格一致。
- 表单具备校验与友好提示；关键操作（删除、危险控制、批量控制）二次确认。

### 8.3 连接参数与接入流程

- 通用参数：设备编号（唯一）、设备名称、设备类型、所属区域、安装位置、通信协议。
- 通信参数：按所选协议动态展示（IP/端口/串口/波特率/从站地址/Broker/Topic/Token/节点 ID 等）。
- 采集参数：采集周期、心跳周期、超时时间、重试次数、启用状态。
- 接入流程：① 选设备类型 → ② 选通信协议 → ③ 填连接参数 → ④ 测试连接（模拟）→ ⑤ 保存并上线 → ⑥ 生成接入记录。
- 校验规则：设备编号唯一非空；IP 格式合法；端口 1~65535；数值型在允许范围；测试连接未通过不得上线。

| 控制点 | 类型 | 取值范围 | 适用设备 |
| --- | --- | --- | --- |
| power | 枚举 | on / off | 空调、照明、插座、办公设备 |
| mode | 枚举 | cool / heat / fan / auto | 空调、新风 |
| temperature | 数值 | 16 ~ 30 | 空调 |
| fanSpeed | 枚举 | low / mid / high / auto | 空调、新风 |
| brightness | 数值 | 0 ~ 100 | 照明 |
| powerLimit | 数值 | 0 ~ 额定功率 | 充电桩、配电 |
| switch | 枚举 | open / close | 断路器、配电柜 |
| chargeMode | 枚举 | charge / discharge / idle | 储能 |

### 8.5 指令模型与状态流转

- 指令模型：指令编号、目标设备、控制点、目标值、优先级、执行方式（立即/定时）、定时执行时间、超时时间、是否需要二次确认、操作人、下发时间。
- 下发流程：① 选设备 → ② 选控制点 → ③ 设目标值 → ④ 二次确认（危险/批量）→ ⑤ 下发 → ⑥ 等待响应 → ⑦ 更新状态并记录。
- 状态：待下发 → 下发中 → 执行成功 / 执行失败 / 超时。
- 安全规则：控制需权限；危险控制点（分闸、断电、功率上限变更）需二次确认且需高级权限；批量控制需提示受影响设备数量与范围；所有控制指令留痕且不可删除。

### 8.6 模拟实现约定（V1.0）

| 环节 | 模拟方式 |
| --- | --- |
| 测试连接 | 按预设规则返回结果（如参数完整即成功），返回模拟耗时 |
| 设备上线 | 将设备状态置为"在线" |
| 数据采集 | 按设备类型定时生成符合量纲与量级范围的模拟测点数据 |
| 控制下发 | 生成指令记录，延时后返回"执行成功"并同步更新设备状态 |
| 告警产生 | 按告警规则判定模拟数据，命中即生成告警 |
| 通信超时 | 可配置一定比例模拟超时/失败，用于演示异常场景 |
| 消息通知 | 邮件、短信按模拟方式发送，仅记录发送记录 |

### 11.3 启动步骤

**后端**

```bash
cd backend
uv sync                                  # 安装依赖
uv run python -m app.db.init_db          # 建表
uv run python -m app.seed.run_seed       # 基础数据
uv run uvicorn app.main:app --reload --port 8000
```

**前端**

```bash
cd frontend
pnpm install
pnpm dev                                 # 开发服务器（默认 http://localhost:5173）
```
